## 3. 持ち票の計算（最重要）

### 仕様
- **持ち票 ＝ 今月の付与合計 ＋ 繰越**
- **今月の付与合計**
  - その期の GRANT に記録されたプランの票を合計する。同じプランは1回だけ数える。
  - 例: サポーター→パートナーに変更した月は、12+40=52。
  - 合計が現プランの基本票より少なければ、基本票を最低保証する。
- **繰越**
  - 前月の残り＋前々月の残りを足す。3か月以上前の分は消える。
  - **票は古い繰越から先に使う**（消費順序：前々月の残り → 前月の残り → その月の付与）。各月の「残り」は、連続して会員だった月を古い順にたどって計算する（`calcCarryBreakdown` / `calcServerLimit`）。
  - 前月に会員でなければ繰越は0。前々月の残りは、前々月「と」前月の両方で会員だったときだけ使える。
  - 「会員だった月」とは、GRANTがある月、または投票記録がある月。
  - その月のGRANTが0件なら、その月に投票したときのプランの基本票で代用する。
- **使用**
  - 同じ期（termId）に属する全イベントの票を合計する。

### 同じ計算が書かれている4か所
| 場所 | 関数 | 使われ方 |
|---|---|---|
| 投票者画面 | `getGrantedThisTerm` + `getCarryOver` → `getTotal`（`index.html:1053-1124`） | 残り票の表示と入力の上限 |
| 管理画面 | `calcMemberVotes`（`index.html:1844`） | 会員一覧・繰越タブ・超過判定 |
| 共通部品 | `calcCarryOverGeneric` / `calcCarryBreakdown`（`index.html:1067-1110`） | 上の2つから呼ばれる |
| GAS（**最終判定**） | `calcServerLimit`（`gas/iito_gas_api.gs:228`） | 投票を受け付けるかどうかの判定 |

- プランの票数も2か所にある: `PLANS`（`index.html:696`）と `PLAN_VOTES`（`gas/iito_gas_api.gs:13`）。**必ず同じ値にする。**

## 票の付与を「支払いが確定した日」に変更（2026年12月期から）

  - 理由：毎月1日の付与は、今月分の支払いを確かめる前に配っていた。そのため、前月の10日にプロデューサーで払った人が今月3日にパートナーへ下げると、今月は払っていないプロデューサーの150票と、払ったパートナーの40票の両方（190票）を受け取れてしまっていた。
- 2026年11月期までは、従来どおり（毎月1日に付与）。境目は、HTMLの `PAY_GRANT_FROM` と GASの `PAY_GRANT_FROM`（どちらも 202612）。
- `grantsFromHistory`：12月期以降は、その月の支払いの記録（「解約」以外）だけで付与する。
- 最低保証（記録が無くても現プランの基本票を使える）は、11月期までだけにした。画面の `getGrantedThisTerm` と `calcMemberVotes`、GASの `calcServerLimit`。12月期からは、記録された付与の分だけ使える。**GASの再デプロイが必要（12/1まで）**。
- 決済履歴を見る限り、プランを下げた記録は次の更新日（支払いの日）に入り、上げた記録はその日に入る。
- 利用規約の第3条第2項・第3項を改定した（2026-12-01から適用、11月までは改定前の規定）。
- 2026-11-21 追記：マイページに「次の付与予定（更新日）」を表示（`nextGrantInfo` / `renderNextGrant`）。表示は2026年12月から（11月中は出さない）。上部の残り票数の下にも1行で出す。
  - 更新日＝会員データの最終決済日（F列）の1か月後。月末は、その月の末日にそろえる（例：10/31 → 11/30 → 12/31）。11月中の更新日は飛ばして、12月期以降の最初の更新日を出す。
  - 「今のプランのまま更新した場合」の予定（まだ使えない）として、今のプランの票数を出す。支払いが確定し、CSVを読み込んで付与が記録されたら「本付与」（使える）。更新日を過ぎてもまだ記録されていなければ「本付与待ち」と出す。12月期以降の付与履歴の行には「本付与済み」と出す。
  - GASの `findMember_` / `findMemberByEmail_` が、本人の分だけ最終決済日（`paidAt`）を返すようにした。**GASの再デプロイが必要**（入れ替えるまでは、この表示は出ないだけで、他には影響しない）。

## 投票画面の「応援ランキング」（2026-11-21）

- 投票画面のイベントのバナーの右側に、半透明の枠を重ねて表示する（`sr-panel`、`refreshSupporterRank` / `renderSupporterRank`）。
  - 中身：自分がこのイベントで票を入れたモデルについて、いま誰が何票入れているか（上位5名のニックネームと票数）。同じ票数は同じ順位。
  - 自分が5位より下なら、下に「あなた：○位 ○票」を出す。複数のモデルに入れていれば、上のタブで切り替える。
  - リアルタイム：投票画面を開いたとき、イベントを切り替えたとき、送信に成功したとき、表示中は60秒ごとに取り直す。
  - 「最小化」で小さなボタン（「応援ランキング あなた ○位」）だけにでき、押すと元の大きさに戻る。最小化したかどうかは端末ごとに覚える。
- GASの `supporterRank`（本人確認あり）：本人がこのイベントで票を入れたモデルの分だけ、ニックネームと票数を返す。メールアドレスや会員番号は返さない。集計は20秒だけキャッシュする（`supporterAgg_`）。**GASの再デプロイが必要**。
- ニックネームを他の会員に見せるため、利用規約（第5条第5項）とプライバシーポリシー（3. 利用目的）を改定した（2026-11-23から適用）。名前の扱いは「全員ニックネームで表示」（運営の決定、2026-11-21）。
- 2026-11-21 追記：応援ランキングは、そのイベントでそのモデルに10票以上入れた人だけが見られる（GASの `SUPPORTER_MIN_VOTES`）。10票未満のモデルは中身を返さず「あと○票」だけ返し、画面は鍵マークの案内を出す。どのモデルにも10票未満なら、右上に「応援ランキングは10票以上で表示 あと○票」の小さな表示だけ出す。規約（第5条第5項）とポリシーも「10票以上」に合わせた。

## ログイン状態の保持（2026-11-22）
- 一時的なエラー（サーバー混雑・GASの例外・会員情報の更新中の not_member など）では、ログイン状態を消さない。消すのは `auth_required`（証明の期限切れ・パスコード再設定）と `email_mismatch` のときだけ（`isAuthHardError`）。
- ログインの有効期間：**最後に使ってから30日**。期限が投票期間（イベントの開始〜終了）に重なる場合は、その投票期間の終了の翌日まで延長（`voterTokenExp_`、イベント期間は5分キャッシュ）。→ 投票期間中は一度ログインすればログアウトされない。
- `me` を呼ぶたびに、GAS が上のルールで期限を付け直した新しい証明を返し（1時間以上ずれるときだけ、`renewVoterToken_`）、HTML が保存し直す。HTML 側は証明の期限で自動ログインの可否を判定（`sessionAlive`）。旧方式（メールリンク）は従来どおり90日。
- GAS の再デプロイが必要（延長の部分）。デプロイ前でも、エラー時にログアウトしない部分は HTML だけで有効。
